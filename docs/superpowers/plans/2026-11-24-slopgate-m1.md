# slopgate M1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When a coding agent finishes a task in a Python repo, find each new function that reimplements an existing one, prove it by running both on generated inputs in a sandbox, and block the agent with the proven findings.

**Architecture:** Two Claude Code hooks call one CLI. `slopgate start` (UserPromptSubmit) snapshots the repo; `slopgate check` (Stop) diffs against the snapshot, indexes functions with stdlib `ast`, retrieves look-alike candidates by embedding similarity, and proves equivalence by running both functions in a sandboxed subprocess of the repo's own interpreter.

**Tech Stack:** Python 3.11+, stdlib `ast`/`subprocess`/`pickle`, `hypothesis` (input generation), `fastembed` (local embeddings), `pytest`.

**Spec:** `docs/superpowers/specs/2026-11-24-slopgate-design.md` (M1 = §6.1–6.4, §6.6, §6.8 for reinvention only, §6.9, and the stats §7 needs for the go/no-go bar).

## Global Constraints

- Python 3.11+. Analyzes Python repos only.
- All state lives under `<repo>/.git/slopgate/`, never in the working tree.
- No code leaves the machine. Downloading the embedding model is the only network use.
- **Report only proven findings.** No verdict means silence, never a guess.
- Hooks must never break the user's session: any internal error → exit 0, allow, and say so in the summary.
- Prover: 200 inputs per pair; ≥50 inputs must return normally in both; floats compared exactly with NaN equal to NaN; return types must match; arguments compared after the call (fresh deep copy per run); self-disagreement on a 20-input re-run means no verdict.
- Prover isolation: subprocess per function batch, throwaway working directory, `PYTHONDONTWRITEBYTECODE=1`, per-call timeout 1 s, batch timeout 10 s, OS sandbox (`sandbox-exec` on macOS, `bwrap` on Linux when installed); without one, the summary says "running unsandboxed".
- Prover interpreter: `<repo>/.venv/bin/python`, else `$VIRTUAL_ENV/bin/python`, else `python3`.
- Latency budget: 20 s per `check`; candidates not reached are counted as skipped.
- Rounds: rounds 1–2 may block; round 3+ never blocks; a round whose findings equal the previous round's never blocks.
- Commit messages are short, with no attribution trailers.

## Review Focus

- **A function that writes a file through a helper the AST check can't see:** the sandbox must stop the write, and no file appears outside the workdir. — Task 5
- **A function that never returns:** the timeout ends it, the pair gets no verdict, and `check` still finishes. — Task 5
- **A repo file with a syntax error** (the agent left it half-edited): indexing skips that file, and `check` still runs. — Task 2
- **`check` with no snapshot** (start hook never ran, or not a git repo): allow the stop with an explanatory message, never crash or block. — Task 8
- **More candidates than the 20 s budget allows:** stop proving, report the skipped count, and still return within budget. — Task 7

### Task 4: Judgeability

**Files:**
- Create: `src/slopgate/judge.py`
- Test: `tests/test_judge.py`

**Interfaces:**
- Consumes: Task 2 `FunctionInfo`.
- Produces: `why_not_judgeable(fn: FunctionInfo) -> str | None` (`None` means the prover may run it; otherwise a short reason used in coverage stats).

Not judgeable when any of: async; generator; a method (any function in a class); a parameter without an annotation; an annotation outside the allowed set (below); the body references a denied name. Allowed annotations: `int`, `float`, `str`, `bytes`, `bool`, `None`, and `list`/`dict`/`tuple`/`set`/`frozenset`/`Optional`/`Union`/`X | Y` built only from those. Repo-defined types are excluded so the parent process never imports repo code. Denied names (any `Name` or `Attribute` root in the body): `open`, `print`, `input`, `exec`, `eval`, `compile`, `__import__`, `globals`, `setattr`, `delattr`, `os`, `sys`, `subprocess`, `socket`, `shutil`, `pathlib`, `Path`, `requests`, `httpx`, `urllib`, `sqlite3`, `time`, `datetime`, `random`, `uuid`, `secrets`, `threading`, `asyncio`, `multiprocessing`, `logging`.

### Task 5: Sandboxed runner

**Files:**
- Create: `src/slopgate/sandbox.py`, `src/slopgate/child.py`
- Test: `tests/test_sandbox.py`

**Interfaces:**
- Consumes: Task 2 `FunctionInfo`.
- Produces: `Outcome = tuple` with shapes `("return", value, args_after)`, `("raise", exc_qualname, args_after)`, `("timeout",)`, `("error", message)`; `run_batch(repo: Path, fn: FunctionInfo, inputs: list[tuple], interpreter: str) -> list[Outcome] | None` (`None` when the module fails to import or the batch times out); `pick_interpreter(repo: Path) -> str`; `sandbox_kind() -> Literal["sandbox-exec", "bwrap", "none"]`.

`child.py` is run by file path (not `-m`, so it needs no install in the repo's environment): it reads a pickled `(repo_root, module, qualname, inputs)` from stdin, adds `repo_root` and `repo_root/src` to `sys.path`, imports the module, runs the function on a fresh `copy.deepcopy` of each input with a 1 s `signal.setitimer` per call, and writes the pickled outcome list to stdout. An unpicklable return or argument becomes `("error", "unpicklable")`.

`run_batch` runs the child with the throwaway workdir as cwd, `PYTHONDONTWRITEBYTECODE=1`, a 10 s timeout, and the OS sandbox. The exact profiles:

```
; sandbox-exec -p "<profile>" <interpreter> child.py
(version 1)
(allow default)
(deny network*)
(deny file-write*)
(allow file-write* (subpath "<workdir>") (literal "/dev/null"))
```

```
bwrap --ro-bind / / --dev /dev --proc /proc --bind <workdir> <workdir> --unshare-net --die-with-parent <interpreter> child.py
```

### Task 6: Equivalence prover

**Files:**
- Create: `src/slopgate/prover.py`
- Test: `tests/test_prover.py`

**Interfaces:**
- Consumes: Task 4 `why_not_judgeable`, Task 5 `run_batch`, `Outcome`.
- Produces: `generate_inputs(fn: FunctionInfo, n: int = 200) -> list[tuple]`; `same_outcome(a: Outcome, b: Outcome) -> bool`; `prove(repo: Path, f: FunctionInfo, g: FunctionInfo, interpreter: str) -> Verdict`; `Verdict(equivalent: bool | None, inputs: int, reason: str)` (`None` = no verdict).

`generate_inputs`: build `st.tuples(*(st.from_type(eval(annotation, typing_namespace)) ...))` from the annotations allowed by Task 4, and collect draws inside a `@settings(max_examples=n, database=None, derandomize=True)` `@given` function that appends each example to a list. Deterministic, so counterexamples are reproducible.

`prove` returns no verdict unless: both are judgeable, have the same `required_arity`, `run_batch` returns outcomes for both, no outcome is `timeout` or `error`, at least 50 inputs `return` in both, and re-running the first 20 inputs gives identical outcomes for each function (nondeterminism check). Equivalent only if `same_outcome` holds for every input.

`same_outcome`: same kind; for `raise`, same exception qualname; for `return`, `type(a) is type(b)` and (both floats are NaN, or `a == b`); and `args_after` equal by `==`.

### Task 7: Retrieval and the reinvention check

**Files:**
- Create: `src/slopgate/reinvention.py`
- Test: `tests/test_reinvention.py`

**Interfaces:**
- Consumes: Task 3 `Changes`, Task 6 `prove`, `Verdict`.
- Produces: `Embed = Callable[[list[str]], list[list[float]]]`; `default_embed() -> Embed` (fastembed with `jinaai/jina-embeddings-v2-base-code`; if fastembed lacks it, the smallest code-capable model it ships); `Finding(new: FunctionInfo, existing: FunctionInfo, inputs: int)`; `CheckResult(findings: list[Finding], new_count: int, judgeable_count: int, skipped: int)`; `find_reinventions(repo: Path, changes: Changes, embed: Embed, interpreter: str, budget_s: float = 20.0, k: int = 5) -> CheckResult`; `format_finding(f: Finding) -> str`.

For each judgeable new function: candidates are existing functions with the same `required_arity` that are themselves judgeable, ranked by cosine similarity of `embed([source])`, top `k`. Embeddings are cached in `state_dir/embeddings.json` keyed by the SHA-256 of the source, so a check only embeds functions whose text changed (spec §6.3's cache requirement; this is where the time goes). Prove in rank order, stopping at the first equivalent candidate. When elapsed time passes `budget_s`, count the remaining new functions as `skipped` and return.

`format_finding` must produce exactly (spec §6.4):

```
api/views.py:41 fmt_date reimplements utils/dates.py:12 to_iso
  (identical on 200 generated inputs). Delete fmt_date (38 lines)
  and call to_iso.
```

Line count is `end_line - line + 1` of the new function.

Hook I/O (confirm against current Claude Code hook docs in Step 1, and adjust only the JSON field names if they changed):
- Both hooks read JSON from stdin and use its `cwd` as the repo.
- `start`: calls `take_snapshot`, prints nothing, exits 0.
- `check` blocking: prints `{"decision": "block", "reason": <findings joined by blank lines>}` and exits 0.
- `check` allowing: prints `{"systemMessage": <one-line summary>}` and exits 0. Summary: `slopgate: N new functions, J judgeable, F findings, S skipped` plus `(running unsandboxed)` when `sandbox_kind()` is `none`.
- Any exception, a missing snapshot, or a non-git `cwd`: allow, with the summary naming the reason.

`install`: merges into `<repo>/.claude/settings.json`, creating it if missing, without duplicating entries already present:

```json
{"hooks": {"UserPromptSubmit": [{"hooks": [{"type": "command", "command": "slopgate start"}]}],
           "Stop": [{"hooks": [{"type": "command", "command": "slopgate check"}]}]}}
```

`rounds.py` keeps `state_dir/rounds.json` as `{task_id, round, last_findings_sha}`. A new `task_id` resets to round 0. `should_block` increments the round; it returns `False` from round 3 on, or when the findings' SHA-256 equals the previous round's.

Every `check` appends one JSON line to `state_dir/stats.jsonl`: `{task_id, round, new, judgeable, findings, resolved, skipped, seconds}`, where `resolved` counts the previous round's findings that no longer appear (the go/no-go input from spec §7).
